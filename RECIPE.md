# black-sun

A calm Herdr window for running Claude Code agents: your spaces in the sidebar with each space's agents folded under it, the agents list below, a **Skills** button that shows exactly which skills each Claude agent has loaded and where they come from, an **MCP** button that shows its MCP servers and whether each connected, and weekly usage bars for Claude, Fable and Codex. Tabs on top, panes as cards, Files and Changes panels on the right, and a **grid view** that shows terminals from any spaces next to each other.

## What you see

- **Sidebar** (268px, resizable 44–480, compact rail under 160px), top to bottom:
  - 46px brand bar (`black-sun-brand`, a copy of Herdr's `workspace-chrome`): a black sun icon (`sun.png`, 112px drawn at 30px: a black disc with a violet corona, on a clear background) and "black sun" in the terminals' font (`settings().font_family`), then Herdr's search and sidebar buttons; drags the window.
  - **Spaces** (`spaces-tree`): Herdr's spaces list (each space's tag instead of a lettered avatar, see Space tags; worktrees under their checkout, grouped by machine) with each space's agents nested under it; chevrons fold one space's agents or all of them; the header's gear opens black-sun settings. Drag a space's row to reorder (`reorder.js`, `space.move`): once the press has moved 6px the space's box goes faint, a small card with its tag and name follows the pointer, and a slot in the accent color with the same tag and name shows where it would land: above the box under the pointer when the pointer is in its upper half, below it in the lower half (same machine only; no slot where it already is). Letting go anywhere in the sidebar drops it at the slot; leaving the sidebar ends the drag without a move.
    Each space is a box (1px `border`, `background`, square corners, 10px under it): its own row edge to edge, then its agents and plain terminals inset 6px all around, 5px apart, each row 30px high, in tab order. A plain terminal (setting `terminals`, on) is named as its tab is in the tab bar (the tab's name, else its program, else "Terminal") and has no status. A space with no agents ends with an **Add terminal or agent** row (setting `emptyAdd`, on): it selects the space and opens Herdr's `new-menu` popup, as + in the tab bar does. Folding a space (its chevron, which such a space has too, or fold all in the header) hides this row with the rest, leaving only the space's own row. A computer's header after the first has 16px above it.
    Each agent row, left to right: its number in a light grey (theme `muted`, 1–9: what ⌘1–9 go to; see Numbers), its icon and name (cut short when long), right after it how long it has been in its status, which always shows (the rest of the row is left for the glow) ("<1m", "5m", "3h", "2d" in `dim`, as Herdr's Agents list counts it: "done" is "idle"; kept in localStorage `agents.changed`, first seen agents start from their tab's `changed_at`; redrawn every 30 s), its status.
    Each agent row: right-click opens the agent menu (`sidebar-menu`); each space row: right-click opens the space menu (`sidebar-menu`); while Auto-name runs, an accent spinner replaces its status.
  - **Agents** (`agents-list`, a copy of Herdr's `agents`; layout block `agents`, min 41): a chevron right of the sort button folds the list to its 41px header (`layout.resize {id: "agents", px: 41}`; folded means the block is at most 45px, so dragging it open unfolds it too) and opens it again (`weight: 1`). On the rail it never folds.
  - **Skills** (`skill-tree`), a 32px row: "◆ Skills · N", N = skills the focused Claude agent has loaded; "◆" only on the rail.
  - **MCP** (`mcp-tree`), a 32px row: "⬡ MCP · N", N = MCP servers the focused Claude agent has; a red dot and "N failed" on the right when any failed; "⬡" (plus the dot) on the rail.
  - **Weekly usage** (`weekly-usage`), 124px: three bars (Claude all models, Fable, Codex) with % used and time to reset; green under 60%, amber to 80%, red above; ↻ refreshes; thin bars on the rail.
  - 69px footer (Herdr's `workspace-chrome`): Settings, Add machine.
- **Work area**: 42px tab bar (`black-sun-tabs`, a copy of Herdr's `tabs`: each tab square, with its space's tag as an 8px square, the shown one with a highlight border and the fade behind it, the tab's status as the glow, pulsing while working in place of the spinner; all as a grid view card's title, see Colors) with the grid view buttons at its right end, the shown tab's panes as cards (radius 0), a hidden 368px right panel stacking Files and Changes, a 28px status bar (Herdr's `workspace-status`). In grid view the tab bar and the cards are replaced by the grid's own (see Grid view).
- No title bar of its own look: `titlebar: none`, macOS traffic lights at [12, 16], `canvas` background, terminal padding [14, 12]. Theme and fonts are yours.

## How it behaves

- **Skills dialog** (560×640): clicking the Skills row opens it on the focused agent.
  - An **Agent** dropdown lists every agent on this computer as "space / tab" with its program icon from Herdr's program table (the focused one marked), then **Global**. Claude Code agents show what they loaded; other agents (Codex, …) are marked ".agents skills" and show the shared folders instead (their folder comes from Herdr's `panes()`); one whose folder isn't known is dimmed and marked "folder unknown".
  - Agent view: the skills that session actually loaded, from Claude Code's own session log, grouped: **This project** (`<cwd>/.claude/skills`), **This project · .agents/skills** (`<cwd>/.agents/skills`, read from disk: Codex and others read that folder, Claude Code doesn't load it, so these aren't in the row's count; a name the session already lists isn't repeated; shown even when the session has no skill list yet), **Yours** (`~/.claude/skills`), **claude.ai account**, **Plugins** (one group per enabled plugin), **Built into Claude Code**. Each skill: its name in full white (group names are larger but dimmer), the full description on hover, and an **ⓘ**.
  - A non-Claude agent's view: an inventory of the folders it can read, not what it loaded: **This project · .agents/skills** (`<cwd>/.agents/skills`, the agent's current folder only, no parent folders), then **Yours** (`~/.agents/skills`); the project's copy wins a shared name.
  - Global: installed Claude skills plus shared personal skills from `~/.agents/skills` under Yours, account skills, every enabled plugin's skills, plus built-ins. Same-name personal skills appear once, preferring the Claude copy. Shared-only skills show their actual source and scope in the info dialog; this inventory does not imply an agent has loaded them.
  - Every group starts folded; opening one shows its next level folded too (Plugins → one row per plugin). Which groups are open is kept in Herdr's shared state (`skill-tree.open`), so the next dialog — and the next start — opens the same way. ↻ reloads, ✕ or Esc closes. A session with no skill list yet says so and offers Global.
- **Plugin info dialog**: the ⓘ on a plugin's row shows its `plugin.json` (description, version, author name — never the email —, license, homepage), marketplace and repo, installed commit and dates, what it ships (skills, commands, agents, hooks, MCP servers), its folder, and `claude plugin update|disable|enable|uninstall`.
- **Skill info dialog** (520×600): clicking a skill or its ⓘ opens it on top of the Skills dialog; ✕ or Esc closes just it. Everything is read from disk, nothing generated:
  - Kind (Project, Project · shared, Personal, claude.ai account, Plugin, Built into Claude Code) and where it applies.
  - Description: the skill's own, from its `SKILL.md` front matter (or the session's listing when there's no folder).
  - Source: plugin name and version plus marketplace and its GitHub repo (`installed_plugins.json`, `known_marketplaces.json`); for personal skills, `npx skills` and its repo (`~/.agents/.skill-lock.json`), the git repo it lives in, or "made by hand", plus the link it's reached through and the folder that link points to (also named in Remove); the Claude Code version for built-ins (from the `~/.local/bin/claude` link).
  - On disk: the path (links resolved), **Reveal in Finder**, **Copy**.
  - All of its text (description, source, path, steps, commands) can be selected and copied with ⌘C (gpui-base `TextView.html(...).selectable(true)`).
  - Update and Remove: what to do, with commands to copy (`claude plugin update|disable|uninstall <plugin>@<marketplace>`, `npx skills update`, `npx skills remove --global <name>`, `git -C <repo> pull`, `claude update`). Nothing is run.
- **MCP dialog** (560×640): clicking the MCP row opens it on the focused agent, with the same Agent dropdown, Global, folding (kept in `mcp-tree.open`), ↻ and ✕ as the Skills dialog. The header says "N/M connected · K failed".
  - Agent view: every server the session knows, grouped: **This project** (`<cwd>/.mcp.json`), **This project, just you** (`~/.claude.json` → `projects[cwd].mcpServers`), **Yours** (`~/.claude.json` → `mcpServers`), **claude.ai connectors** (seen as `claude_ai_<Name>` tools), **Plugins** (one group per enabled plugin, from its `.mcp.json` or `plugin.json` `mcpServers`), and **Other** for tools of a server found nowhere else. A name in several scopes shows once, where Claude Code takes it from: local, then project, then user.
  - Each server row: a status dot (theme `done` connected, `blocked` failed, `working` connecting, `dim` configured but not loaded), its name, its tool count or "failed", the error on hover, and an ⓘ. A group with a failed server anywhere under it (Plugins → github) gets a red dot after its count, so a failure shows while folded.
  - Status comes from the session log's `deferred_tools_delta` records (tools added and removed, named `mcp__<server>__<tool>`, plus the current `failedMcpServers` and `pendingMcpServers`) and `mcp_instructions_delta` (each server's instructions). After a `compact_boundary` Claude Code re-adds everything, so the state starts over there.
  - Global: your servers and plugins' servers, status "not checked" (there's no session to ask).
- **MCP server info dialog** (520×640): status or error; **Fix it** (when a failed server's config reads `${VAR}`s from the environment it names them, since an unset one empties that part of the config; then `claude mcp login <name>` for HTTP servers, and `/mcp` or a restart to reconnect); its tools; the instructions it gives Claude; its config as Transport, URL (no credentials or query), Program (name only), Arguments (count only), Headers and Environment (names only), Reads variables; its source; and Update/Remove commands to copy (`claude mcp get|remove <name> -s user|local|project`, run in the project folder for local and project; `claude plugin update|disable|uninstall <plugin>@<marketplace>`; claude.ai Settings → Connectors). All text selectable. Nothing is run.
- **Agent names.** Each agent has two names for the same thing: its sidebar row's (at most 5 words) and its tab's (at most 3). `spaces-tree` keeps, per tab, the pair it gave (localStorage `agent-names.given`: tab id → `{tab, row, by: "sync" | "auto"}`); the row shows `row` while the tab still carries `tab`. A name a person types (Rename) is the tab's name and shows on the row too. The Agents list shows the tab's name.
  - Sync: when a tab holds exactly one agent and nobody named it (or only with the agent's program name, as Herdr's launcher does), or sync named it and it still carries that name, the agent's telling title (not the program's name, a path or user@host) gives both names. Codex titles "[status | ]thread | folder" give just the thread title, and a status-only title waits. Row: the title cut to 5 words. Tab: the title if it's 3 words or fewer, else Haiku's shortening of the title alone ("AT MOST 3 words" prompt with two examples), remembered per title in localStorage `agent-names.short.v2`, or the title trimmed if Haiku fails. Cutting drops little words ("and", "the", "to"…) first. A person's rename, Auto-name's names, or a reset to the automatic name are never touched. Tabs with several agents are left alone.
  - `<new>`: a one-agent tab whose agent has no telling title yet (a Codex status alone counts as none), and that sync hasn't named, is named `<new>`, so its tab and row both read `<new>`; agents started from the space menu or ⌘⇧C/⌘⇧X are created with that name, those from Herdr's + get it from sync. Sync treats `<new>` like the program's name: the first telling title replaces it.
  - Agent menu (230×195 popup, Herdr's menu look): **Rename** (hint: the key bound to `tab.rename`, F2) asks for the tab's name; **Auto-name** (hint: the key bound to `spaces-tree.auto-name`, ⌘⇧R from the `layout:black-sun` section of `keys.json`) sets `shared("agent-names.request") = {terminal, at}` for spaces-tree. Auto-name is dimmed for agents that aren't Claude Code or Codex on this computer. Under it, **Auto-name all** (hint: `spaces-tree.auto-name-all`, ⌘⇧A) sets `{all: true, at}`. **Open in Finder** (folder icon; hint: `spaces-tree.open-finder`, ⌘⇧F) sets `shared("black-sun.finder") = {terminal, at}` for spaces-tree; dimmed for agents on another machine. Then, below a line, **Close** (`tab.close`, hint cmd-w) when the agent is alone in its tab, else **Close pane** (`pane.close {pane}`, cmd-shift-w) so the tab's other panes keep running; Herdr confirms when something runs. ↑/↓, Enter, Esc.
  - ⌘⇧R (`spaces-tree.auto-name` through `nextCommand`) names the focused agent; ⌘⇧A (`spaces-tree.auto-name-all`) names every Claude Code and Codex agent on this computer, three at a time, each row spinning while it's named, with one toast listing any that failed ("Named N of M agents").
  - Open in Finder: ⌘⇧F (`spaces-tree.open-finder` through `nextCommand`) for the focused agent, or the agent menu's item; runs `open <folder>` on the agent's pane's live folder (`panes()[i].cwd`), else its space's folder. Agents on this computer only; a toast says why when there's no focused agent, it's on another machine, the folder is unknown or `open` fails.
  - Auto-name: the agent's log (Claude: `~/.claude/sessions/<pid>.json` matched by `HC_TERMINAL_ID`; Codex: the newest of the 40 newest rollouts whose `cwd` is the agent's folder, refused when another Codex agent shares it), its last 3 MB; the last 6 user messages and everything said after (assistant text only, no tool output, thinking, injected context or meta records; each ≤ 400 characters, all ≤ 4,000); `claude -p --model haiku --no-session-persistence --tools "" --setting-sources ""` from the home folder, the excerpt on stdin, asking for two lines "Row: ≤ 5 words" and "Tab: ≤ 3 words"; each without quotes, markdown, labels or a final period, ≤ 60 characters, trimmed to its word limit; then `tab.rename` with the tab name. One run per agent; a failure toasts why and keeps the names.
- **Space menu** (`sidebar-menu`, popup 240 wide; replaces Herdr's own space menu on black-sun's space rows): "Start an agent", then every installed agent from `knownAgents()` (as Herdr's + menu lists them, with their program icons; cached in the + menu's shared `new-menu.agents`), each started in *this* space by spaces-tree (`tab.new {name: "<new>", space, argv}`, see New agents from anywhere), hinted with its hotkey or its number (1–9 keys work); **Terminal** (`tab.new {space}`, cmd-t). Below a line, Herdr's own space items: Rename (`space.rename`, shift-f2), New/Open worktree when the space is a git checkout, Remove worktree for a linked one (the `worktree` dialog), then under a "Tag" header one item per space tag (its color as a dot, ✓ on the space's own; picking that one untags the space) and **Edit tags…** ("Add tags…" while there are none), which opens black-sun settings; and below another line Close (`space.close`). The popup is 500 + 31 per tag high at most. The checkout comes from spaces-tree's git info.
- **Settings** (`black-sun-settings`, opened by the gear between fold-all and + in the Spaces header; `settings.svg` from workspace-chrome). It is a window (`openOverlay {kind: "window", key: "black-sun-settings"}`): dragged by its title bar (the body stops presses), it opens where it was left; Esc or ✕ closes it. − and + in the title bar step through five sizes (520×640, 640×760 the default, 760×860, 900×960, 1040×1040): the size is kept in the settings and the window is opened again at it under the same key. Shared state `black-sun.settings` = `{sync, rowWords, tabWords, haiku, usageMinutes, highlight, highlightSlot, terminals, emptyAdd, keepSpaces, numbers, wash, fade, glow, pulse, windowSize}` (defaults true, 5, 3, true, 5, `#8b7cf6`, 7, then all true, `numbers` "global", [640, 760]; row 3–8, tab 2–4 and never more than the row, minutes 1/5/15/30), set live; Reset puts the defaults back but keeps the window's size. Sections:
  - Sidebar: a switch per layout block `agents`, `skills`, `mcps`, `usage` (`layout.toggle {id}`; Herdr keeps `hidden` in the layout); **List terminals too** (`terminals`); **Offer to add in empty spaces** (`emptyAdd`); **Spaces stay when empty** (`keepSpaces`); **Numbers** Global | Per space (`numbers`).
  - Colors: see Colors.
  - New agents: **yolo mode**, kept in `programs.json` (not shared state), since that's where every menu and layout gets an agent's start command (`run`). On adds `--dangerously-skip-permissions` to `claude`'s run and `--dangerously-bypass-approvals-and-sandbox` to `codex`'s (`codex --no-daemon` by default), keeping other entries and a person's own commands; off takes the flags out and drops a `run` left equal to Herdr's own. The switch reads the file when the dialog opens ("some" when only one has it), writes with `writeTextFile` (expected = what it read), and clears the menus' cached agents (`new-menu.agents`).
  - Agent names: `sync` off stops naming tabs after titles (and turns `<new>` tabs back to Herdr's automatic name); `rowWords`/`tabWords` go into sync, the row label and both Haiku prompts; `haiku` off cuts long titles with `shortTitle` instead of asking Haiku. Shortenings are cached per word count (localStorage `agent-names.short.v3`, keys `<tabWords>|<title>`).
  - Weekly usage: `usageMinutes` (weekly-usage checks every 30 s whether that long has passed).
  - Hotkeys: the five ⌘⇧ keys and the key each action has (`keys()`, global or `layout:black-sun`), and one row for ⌘1–9 (how many of the nine are `spaces-tree.go-<n>` in `layout:black-sun`); **Add missing keys** reads `keys.json`, adds the unbound ones to `layout:black-sun` unless that key already does something else there or in global (it says which; ⌘1–9 are taken over when global has Herdr's own `tab.select:<n>`, since a layout's section wins), and writes it with `writeTextFile` (expected = what it read).
  - Look: opens `app.settings {section: "look"}`.
- **Colors.** Shared state `black-sun.palettes` = `{current: <palette id>, palettes: [{id, name, colors}]}` (`palettes.js` in `black-sun-settings`, pure, with tests). Every palette has 12 colors. Fifteen are built in (ids `b1`–`b15`: Black Sun, Nord, Catppuccin, Dracula, Gruvbox, Solarized, Tokyo Night, Rosé Pine, Violet Hour, Sunset, Ocean, Forest, Pastel, Neon, Blue & Orange); a person's own are `p1`, `p2`, …
  - Every color chosen in settings (a tag's, the highlight) is one of the selected palette's, kept by its place there (`slot`) next to the color itself, so mods that only draw read the color. Selecting another palette, or changing one of its colors, rewrites every tag's color and the highlight (`repaint()`; `tags.js` `recolor()`). A tag or highlight from before palettes takes the place of the closest color.
  - Settings, section "COLORS": the selected palette's name and strip, **Change** opens the list (click one to select it); the selected one has a name field, **Duplicate** (a copy right after it, selected; the way to make your own), **Remove** (never the last), and its 12 colors: click one for the picker (a preview, a hex field, and Hue / Saturation / Brightness sliders, gpui-base `Slider`; a drag is saved when let go). **Restore the built-in palettes** brings back removed ones and resets edited ones, keeping a person's own.
  - **Highlight color**: 12 swatches of the selected palette. It marks the one with the keyboard: its sidebar row (a 3px bar down the left and a tint), its tab in the tab bar, its grid view card title, its card's border, its pane's border in the normal view, and the border of its space's box in the sidebar (2px; the shown space; in grid view, the space of the focused terminal). The pane's border is the layout's own pane look (`main`'s `content.pane`): `side-by-side`'s switch keeps `focus` at `{width: 2, color: <highlight>}` and `border.width` at 2 with `layout.set`, as it does the cards.
  - **Gradients on spaces** (`wash`, off by default): a tagged space's row has its color coming in from the left edge (50% strong at the edge, gone by 45% of the width) in place of the square, its name at the row's left. **Gradients on agents and terminals** (`fade`): the focused one starts in its space's tag color (60%) and has become the highlight's tint (22%) by 70% of the width, easing in and out; with no tag it is the plain tint. **Show status as a glow on the right** (`glow`): the last 20% of the width, faint for most of it and gathered at the edge (alpha rises with the 2.2 power): working `#e0b23a`, done `#3b9eff`, needs you `#e5534b`, all three as wide and as strong (85% at the edge), idle `#7f8ea3` at 18%; a plain terminal has none. With the glow on, nothing else marks status: no spinner, dot or "Needs you" badge on the sidebar row (their 14px is kept), the tabs or the card title. **Working agents pulse** (`pulse`, needs `glow`): a working agent's glow, the same shape as the others, has its opacity swinging natively (`.loop("opacity", …)`) between 30% and full with a period of 1.4 s. These are the same on the sidebar row, the tab in the tab bar and the grid view card title.
  - `fade.js` holds the pure logic (`fade`, `wash`, `glow`, `pulse`, `layers`, tests in `spaces-tree`); the same file sits in `spaces-tree`, `side-by-side` and `black-sun-tabs` (a test checks the copies match). An element takes one flat color, so each gradient is thin slices side by side, `{color, grow}`: many where the color changes (80 for the fade, 72 for the glow, 48 for the wash; no step over 4 of 255 a channel), one for each flat part.
- **Grid view** (`side-by-side`; "grid view" everywhere a person reads it). Shared state `black-sun.sbs` = `{on, arrange: false | "edit" | "drag", carry: <terminal> | null, root}`. `root` is a tree of splits, null when empty: a node is a terminal's address or `{id, dir: "row" | "col", items}`; kept simple (no empty split, none with one item, none inside one of the same direction). Terminals come from any space, each at most once.
  - Buttons at the right end of the tab bar (layout block `sbs-switch`, 96px wide, 318px while on): **Grid N** turns it on and off (N = terminals in it); while on, **Arrange** (Done while arranging) and **Side by side** (everything in one row, sizes reset). Commands: `side-by-side.toggle`, `.arrange`, `.row`, `.add-<terminal>`, `.remove-<terminal>`.
  - On: `main` and `tabs` hide, `sbs` and `sbs-tabs` show. The switch's copy of the mod keeps the layout in step with the state (`layout.set`): `sbs` becomes the tree as rows and columns (`sbs-split-<id>`, gap 8) of cards (`sbs-<terminal>`: a column with a 2px border, a 30px `head` block of this mod over a `{terminal}` block), for the terminals that are running; splits and cards already there are kept, so dragged sizes stay. The focused terminal's card has its border in the highlight color, so the layout is set again when the keyboard moves (the border is 2px either way, so no terminal is resized). Off: the cards go, and Herdr's tabs are back.
  - Top bar while on (`sbs-tabs`): no tabs, since each card's title is one: "Grid view · N" and **+**, a popup of every terminal not shown yet; it still drags the window. Card title: tag square, icon, name, space, the fade and glow; click focuses, ✕ takes it out, right-click for the agent menu, and dragging it picks the card up.
  - Adding: the agent menu's **Add to grid view** / **Remove from grid view**, the space menu's for all of a space's terminals, dragging an agent row from the sidebar, or +. A new one goes at the grid's right edge: the end of a grid that is one row, else a full-height column beside the rest. In the sidebar, agents in the grid have a small grid icon, a click on one focuses it there, and spaces with something in the grid are the selected ones.
  - Arrange view (`sbs-arrange`, in the grid's place): every terminal as a tile (icon, name, space). Whatever is carried (from here, a card title or the sidebar; `carry` in the shared state, since there is no drag between mods) follows the pointer as a chip, and the view works out the drop from its own geometry. The tile under the pointer shows thin outlines of its zones: its middle swaps; each edge has a band (a third of the tile, at most 110px) shared equally among the choices for that edge, from beside the tile alone (innermost) to beside each bigger group that ends at that edge, up to the whole grid (at the edge). The drop is drawn as the tile the terminal would become, where and as big as it would be, and the title line says it ("Goes below …", "Goes right of these 3", "Goes above everything"). Gaps drag to resize (`layout.resize` on the two neighbors, each at least 60px). Right-click a tile for its menu. Dragging something in from outside opens the view and the drop closes it again.
- **Numbers** (`spaces-tree` `numbers.js`, pure, with tests). The number before a row is its tab's. `numbers` "local": the tab's place in its space (placeholder tabs not counted). "global" (the default): 1, 2, 3, … down the sidebar over every space (this computer's spaces first, then other machines' by name), counting only tabs with something listed. `keys.json` binds ⌘1–9 to `spaces-tree.go-<n>` in `layout:black-sun`: local runs `tab.select {id}` on the shown space's nth tab; global runs `pane.focus` on the first pane listed in the tab with that number (by `{terminal}` when it is shown in grid view), which shows its space and tab. Numbers over 9 aren't drawn.
- **Spaces that stay when empty** (`spaces-tree` `empty.js`, pure, with tests; `black-sun-empty`; setting `keepSpaces`, on). Herdr closes a space with its last tab, so each space keeps a placeholder: a tab named "Empty" whose pane is `black-sun-empty` (a line of text and **Add terminal or agent**, which opens `new-menu`). `spaces-tree` makes it for the shown space when it has none (`tab.new {name: "Empty", space, mod: "black-sun-empty"}`; Herdr shows a new tab, so once `spaces()` has it: `tab.select` back to the tab that was shown, and `tab.settle` the placeholder, which makes Herdr's tab numbers, next and previous skip it). `black-sun-tabs` leaves it out of the tab bar and the numbers don't count it. Shared state `black-sun.empty` = `{<space id>: {tab}}`. When a space's last other tab is closed Herdr shows the placeholder: the space is empty. When something is added (Herdr shows it, and showing had unsettled the placeholder) it is settled again; if Herdr goes to it while other tabs remain, the last other tab is selected instead. Setting off: placeholders of spaces with other tabs are closed and none are made. A space that was never shown since the setting came on has no placeholder yet.
- **Space tags.** Shared state `black-sun.tags` = `{style: "square" | "row", default: <tag id> | null, tags: [{id, name, color, slot}], spaces: {<space id>: <tag id>}}`; a space has one tag or none; `slot` is the color's place in the selected palette (see Colors). `tags.js` holds the pure logic (`normalize`, `tagOf`, `addTag`, `updateTag`, `removeTag`, `recolor`, `assign`, `setDefault`, `tagNew`, `setStyle`, `ink`); the same file sits in `black-sun-settings` (with its tests, which also check the three copies match), `sidebar-menu` and `spaces-tree`, since a mod only imports from its own folder.
  - Settings, section "SPACE TAGS": **Show a space's tag as** Square | Row; **New spaces start with** No tag | each tag (shown once a tag exists); one row per tag: an "Aa" preview in its color, a name field (typing renames), the selected palette's 12 colors as swatches, ✕ to remove (its spaces become untagged, and the default goes if it was this tag); **Add tag** makes one in the least used color and focuses its name.
  - Sidebar, style `square`: with gradients on spaces (the default) the tag's color comes in from the row's left edge instead (see Colors); without, an 18px rounded square in the tag's color before the space's name, no letter, the tag's name on hover. Hollow (a `dim` outline) when untagged, either way; worktree rows keep their branch icon. Style `row`: no square; a tagged space's whole row is filled with its color, its name in `ink(color)` (dark `#14161a` or white, whichever has the higher WCAG contrast: at least 4.5:1 on every swatch) and its git tail and fold at 70% of that; the active one has a 2px `foreground` outline; untagged rows are drawn as before.
  - Default tag: `spaces-tree` keeps the space ids it has seen (localStorage `tags.seen`). The first time, every space there counts as seen and none is tagged; after that a space not seen before gets `default`, unless it already has a tag. A space seen once is never tagged again, so removing its tag sticks.
- **New agents from anywhere**: `keys.json` `layout:black-sun` binds ⌘⇧C to `spaces-tree.new-claude` and ⌘⇧X to `spaces-tree.new-codex`; spaces-tree takes any `new-<program key>` and starts that agent as a new tab in the active space (a toast when it isn't installed). The space menu's agents go through the same path (shared `black-sun.start` = `{key, space, at}`, in that space). Each start asks `knownAgents()` again, so a changed start command (yolo mode) applies at once.
- Agent statuses (working, blocked, done, idle) show as Herdr's `agents` and `spaces` draw them.
- Usage bars refresh every 5 minutes by default (Claude, Fable; the `usageMinutes` setting) and every minute (Codex); hovering a bar shows the reset time and any refresh error.

## Watch out

- **What runs and what is read.** `weekly-usage` reads Claude Code's login from the macOS keychain (`security find-generic-password -s "Claude Code-credentials"`) and calls Anthropic's usage endpoint with it; the token stays inside the shell command. Codex usage comes from the newest `~/.codex/sessions` log. `skill-tree` reads `~/.claude/sessions/<pid>.json` (never the `.key` files beside them), runs `ps eww` on those pids and keeps only `HC_TERMINAL_ID` to match a session to its Herdr terminal, greps the session log for its skill listing, and reads `~/.claude/settings.json`, `~/.claude/plugins/installed_plugins.json`, `known_marketplaces.json`, `~/.agents/.skill-lock.json` and skill folders, including `~/.agents/skills` for Global. Nothing is written; Copy puts text on the clipboard; update and remove commands are only shown.
- **Auto-name sends what was said to Anthropic**: up to 4,000 characters of the session's recent messages go to Claude Haiku through the person's own Claude Code login, for Codex agents too. Only when asked. Sync sends only an agent's title (over 3 words) to Haiku, without asking, to shorten it for the tab. `keys.json` is the person's own file, so the ⌘⇧R binding is added by hand (README).
- **MCP secrets.** MCP configs hold tokens in headers, environment values, arguments and URLs. `mcp-tree` reads `~/.claude.json` only through `/usr/bin/python3 -I` with a filter that prints server entries with those values blanked (argument count kept, `${VAR}` names kept); plugin and project `.mcp.json` go through `stripSecrets` as they're read. No secret value is ever held, shown or copied. Tests check that secret values never come out.
- **Plugin skill folders**: a plugin's `plugin.json` may list its skills at nested paths (`./skills/engineering/tdd`); otherwise they're `skills/<name>`. Its `commands/*.md` show up as skills too. A plugin can ship more skills than a session lists.
- **Claude Code skill listings are incremental**: the session log has one full listing, then partial ones when skills change. The current list is the last full one plus every partial one after it. Removals aren't logged, so a session that lived through a removal still lists the removed skill (under Built-in, having no folder) until it restarts.
- Loaded skills and MCP servers for Claude Code agents only; for Codex and other agents the Skills dialog lists their `.agents/skills` folders, and the MCP dialog lists them dimmed; this computer only; macOS (`security`, `open -R`).
- Herdr rewrites a layout file on `layout.set` and drops fields it doesn't know, so the `source` pointer lives in the mods' `mod.json`.
- **Grid view and the layout.** A mod's `run()` argument may nest only so deep ("a host argument may not nest more than…"): a layout with the grid's cards, or one level of splits, fits (16 levels); a split inside a split doesn't, so `side-by-side` then runs `herdr-app do layout.set <json>` with `exec` instead. A layout node's `focus` border does nothing on a card holding a `{terminal}` block, hence setting the card's own border as the keyboard moves. `structuredClone` isn't there in a mod (JSON round trip). With a zoomed window the numbers given to `.w()`/`.left()` aren't the pixels that sizes and pointer positions are reported in: the arrange view measures a 100-wide probe and places the pointer by its share of the view's bounds.
- **No gradients, no resize handle.** An element's `bg` takes one color (gradients only for layout nodes and painted paths), hence the slices in `fade.js`. A window overlay can be dragged but not resized, and a mod stops getting pointer moves outside itself, hence the settings window's − / + sizes.
- A clicked key in another pane closes an open dialog.

## Install and update

Install: `Read ~/.config/herdr-app/AGENTS.md, then add this layout: herdr.dev/layouts/jorgeper/black-sun`.
Update: replace `layouts/black-sun.json` and the eleven `mods/` folders with this repo's (keep a copy of yours if you changed them); Herdr's "never overwrite" install rule otherwise adds renamed copies.
